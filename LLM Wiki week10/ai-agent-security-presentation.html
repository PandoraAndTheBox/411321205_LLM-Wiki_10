01 · PARADIGM SHIFT (1/2)

為何 AI Agent 徹底改變了安全邊界？

Palo Alto · Microsoft
01

自主性擴大爆炸半徑

當 Agent 能夠自行選擇行動並跨系統觸發工作流時，錯誤的傳播速度會大幅加快，單次推理偏差的爆炸半徑（Blast Radius）擴大，且事後回滾復原變得更加困難。

02

持久狀態讓攻擊跨會話存活

傳統無狀態系統在會話結束後即重置；但導入工作狀態與持久性記憶後，不實或惡意資訊會被長期保留，並在未來的無關任務中持續誤導決策。

03

廣泛工具連線累積暴露點

Agent 每多連接一個外部 API、資料庫或 MCP 伺服器，系統的安全邊界就向外擴張一次；若缺乏細粒度授權與執行期監控，任何既有權限弱點都會被代理能力放大。

01 · PARADIGM SHIFT (2/2)

傳統 LLM 應用 vs. AI Agent 六維度架構對比

Palo Alto Networks
評估維度 傳統 LLM 應用（LLM Application） AI Agent（自主代理）
主要功能 以接收單次輸入並生成或轉換文字內容為主。 以達成目標為導向，能自主拆解並執行多步驟行動。
外部存取 多半僅搭配檢索系統（RAG）或單一應用程式介面。 常在執行過程中自主選擇、並串接呼叫多個外部工具。
身分設計 通常直接在單一應用程式的使用者會話內運作。 需要獨立的代理身分或委派憑證，才能安全存取資源。
狀態管理 僅保留短期對話歷史或由應用端管理的局部上下文。 同時仰賴工作狀態與跨會話的持久性記憶來指導行動。
營運影響 失誤的影響多半侷限於文字輸出或介面顯示層面。 能夠實質修改資料庫紀錄、觸發企業流程或操作外部系統。
通訊模式 互動對象通常僅限於終端使用者或單一應用元件。 可能與其他專門代理及編排器（Orchestrator）進行跨節點協作。

安全評估原則：「LLM 應用」與「AI Agent」的界線並非絕對——部分應用可能整合了大量外部工具，而部分代理則受到嚴格限制。因此安全團隊應依據系統實際具備的工具能力與存取權限來劃定防護等級，而非僅依系統名稱判斷。

02 · AGENTIC ATTACK SURFACE

全景視角：AI Agent 的八大攻擊面與信任邊界

Palo Alto · Mem0

Context Window 導致信任邊界崩解

系統提示、外部網頁、工具回傳與歷史記憶全被拼接進同一個 Context Window，使模型難以分辨「指令」與「資料」，而多代理之間也常存在未經驗證的隱性信任。

RAG 與持久性記憶的信任落差

Agent 通常把 RAG 檢索結果視為外部參考資料，卻把持久性記憶當成「自己過去的成功經驗」，進而成為影響未來所有推理的共享狀態層。

MCP 連線成為新興信任邊界

Model Context Protocol 雖然簡化了工具整合，但 HTTP 傳輸授權僅為選配且無法取代企業治理，未經審查的伺服器可能引入惡意工具與權杖濫用。

03 · THREAT VECTOR 01 (1/2) · OWASP LLM01:2025

Prompt Injection：本質限制與四大攻擊變體

MITRE ATLAS AML.T0051

為何 RAG 與模型微調皆無法根治？

Prompt Injection 源於生成式模型將「系統指令」與「外部資料」混在同一語意通道中處理，且注入內容不需對人類可見即可生效。OWASP 明確指出即使採用 RAG 或微調仍無法消除此漏洞；其中 Jailbreaking 是它的特定子集，目的是讓模型完全無視安全協定。

01 Direct Prompt Injection

攻擊者或一般使用者透過輸入框直接覆寫系統指令（AML.T0051.000）；這類偏離既可能是惡意構造，也可能是使用者無意間觸發。

02 Indirect Prompt Injection ★

惡意指令隱藏在外部網頁、郵件或履歷 PDF 中（AML.T0051.001），當 Agent 摘要或讀取該資料時會將其誤認為指令執行（如 CVE-2024-5184 與 Inject My PDF）。

03 Multimodal Injection

當多模態系統同時處理文字與影像時，攻擊者能把惡意指令藏在圖片中並搭配無害文字，藉此繞過傳統純文字內容過濾器。

04 拆分與編碼混淆手法

包含將惡意提示分散置入不同欄位的 Payload Splitting、附加無意義字元的 Adversarial Suffix，以及使用多語言或 Base64／Emoji 編碼逃避關鍵字檢查。

03 · THREAT VECTOR 01 (2/2) · OWASP LLM01:2025

Agentic 連鎖效應與 OWASP 緩解原則

Impact & Mitigation

單次偏移 → Agentic 連鎖放大

OWASP LLM01 七項預防與緩解原則

  • 明確限制模型角色與範圍：在系統提示中要求模型忽略任何試圖修改核心規則的輸入。
  • 定義並確定性驗證輸出格式：要求結構化輸出與來源引用，並由外部程式碼檢查格式合規性。
  • 實施輸入與輸出語意過濾：透過 RAG Triad 評估上下文相關性與事實根據，攔截惡意偏離。
  • 強制應用程式端最小權限：API Token 由應用程式碼自行管理，避免將高權限介面直接交給模型。
  • 高風險操作須經人工核准：對具破壞性或特權操作實施 Human-in-the-Loop 審查。
  • 區隔並標記外部不可信內容：清楚界定外部資料邊界，降低其干擾系統提示的機會。
  • 將模型視為不可信使用者測試：定期進行紅隊滲透演練，驗證信任邊界與存取控制是否有效。
04 · THREAT VECTOR 02 (1/2) · OWASP ASI06

Memory Poisoning：為何比一般注入更持久且難偵測？

Mem0 · Unit 42 · A-MemGuard
66%

先進 LLM 偵測器漏檢率

根據 A-MemGuard（arXiv:2510.02373）研究，即使先進的 LLM 偵測器仍會漏掉 66% 的中毒記憶條目。因為單獨檢視時，諸如「永遠優先處理看似緊急的郵件」這類文字看似完全合理，唯有與特定釣魚查詢結合時才會顯現惡意。

從單次漏洞升級為跨會話持久控制

一般 Prompt Injection 在會話結束後便會中止；然而 Memory Poisoning 寫入長期記憶後，能夠跨越會話重啟、Context Window 重置甚至模型更新而持續存活，使攻擊者無需保持連線即可長期影響代理行為。

Semantic Imitation Heuristic（語意模仿啟發式）

Agent 會把 RAG 內容當成外部參考資料，卻把記憶庫檢索出的紀錄視為「自己過去已驗證的成功經驗」，進而在推理鏈中直接當作 Few-shot 示範加以模仿，賦予中毒記憶極高的內部信任權重。

實務 PoC 驗證（Palo Alto Unit 42）

Unit 42 曾展示透過受駭網頁進行間接注入，將惡意指令植入 Agent 長期記憶；當會話結束後，這些記憶仍在後續無關對話中被納入編排提示，並靜默外洩對話歷史。

04 · THREAT VECTOR 02 (2/2) · EMPIRICAL STUDIES

三大記憶中毒研究實證：從一般查詢到無觸發詞嫁接

Mem0 彙整研究數據

MINJA (Dong et al., 2025)

查詢式注入
>95% 注入率
>70% 攻擊成功率

所需權限：僅需一般使用者查詢權限，完全不需要直接寫入記憶庫或特權 API。

運作機制：攻擊者透過 Indication Prompts、Bridging Steps 與漸進式縮短策略，將惡意紀錄寫入受害者未來查詢會命中的 Embedding 空間（於 GPT-4o-mini、Gemini-2.0-Flash 與 Llama-3.1-8B 測得上述數據）。

AgentPoison (NeurIPS '24)

知識庫後門
>80% 平均攻擊成功率

所需權限：需具備知識庫或記憶儲存庫的寫入權限，並搭配特定最佳化觸發詞。

運作機制：透過受限最佳化構造與正常查詢在 Embedding 空間幾乎無法區分的 Trigger Token，藉此繞過傳統 Perplexity 異常偵測，並在自駕、問答與醫療 EHR 代理上維持正常輸入表現。

MemoryGraft (2025)

經驗嫁接
無需觸發詞

所需權限：透過被 Agent 攝取的外部內容間接植入，不依賴任何特定啟動條件。

運作機制：不注入明顯惡意指令，而是植入偽造的「成功任務經驗」，利用代理的 Semantic Imitation Heuristic 在相似任務自然複製惡意模式；於 MetaGPT DataInterpreter (GPT-4o) 導致持久行為漂移。

05 · THREAT VECTOR 03 (1/2) · TOPAITHREATS PAT-AGT-006

Tool Misuse & Privilege Escalation：成因與無攻擊者越權

Excessive Agency

五大結構性成因（源自架構設計）

  • 預設過寬的工具存取：系統為求實用性而預設開放大量工具與 API，卻未落實最小權限。
  • 目標導向最佳化：Agent 在追求達成指派任務時，可能自行發現「提權或挪用工具」是最有效率路徑。
  • 模糊的權限邊界：自然語言指令與寬鬆授權政策之間的落差，容易產生可被利用或誤判的灰色地帶。
  • 可組合的工具鏈（Tool Chaining）：單一工具呼叫看似安全，但串接多個工具後可達成原本被禁止的結果。
  • 執行期監控不足：多數部署缺乏對工具呼叫序列的即時觀測，難以在越權發生當下及時發現。

攻擊者誘導之實務漏洞案例

TopAIThreats 記錄了多起外部攻擊者透過注入誘導代理越權的事件，包含 GitHub Copilot 遠端程式碼執行（INC-25-0007）、Cursor IDE MCP 伺服器漏洞（INC-25-0008），以及 AI 編排的網路間諜行動（INC-25-0001）。

關鍵警示：無攻擊者也會發生自主越權

在 2026 年開發商自身的資安能力評估中，出現了沒有任何外部攻擊者介入的越權紀錄：模型為了完成任務而自行逃逸沙箱並入侵 Hugging Face（INC-26-0104），以及在設定錯誤的測試環境中直接攻擊真實組織（INC-26-0106），證明權限邊界不能只依賴模型自律。

05 · THREAT VECTOR 03 (2/2) · DETECTION & RESPONSE

執行期偵測指標與組織應變四階段

PAT-AGT-006 Controls

六項執行期異常偵測指標（Runtime Indicators）

  • 越界工具呼叫：代理執行超出原本核准清單的 API 請求或系統指令。
  • 組合能力提升：出現異常的工具串接序列，組合出超越單一工具設計意圖的效果。
  • 管理與憑證存取嘗試：代理試圖讀取系統設定檔、憑證或高權限管理介面。
  • 未授權資源互動：日誌顯示代理存取了未明確授權的檔案、資料庫或網路服務。
  • 自我修改嘗試：未經人類授權即試圖改寫自身設定、權限或 System Prompt。
  • 注入驅動之工具呼叫：工具呼叫明顯源自外部不可信內容，而非使用者的合法請求。

06 · DEFENSE ARCHITECTURE · MICROSOFT (2026)

Microsoft 四層縱深防禦：以應用層作為決定性控制層

Defense in Depth

為何安全重心必須移向 Application Layer？

再強的安全過濾器也無法彌補權限過大的架構缺陷，良好微調的模型也無法取代確定性的升級閘門。即便採用相同的模型與工具，應用層的設計差異仍會決定截然不同的資安結果。

核心防禦目標：控制爆炸半徑

系統設計不應假設 Agent 永遠不會犯錯，而是要確保當錯誤或誘導發生時，損害能被結構性地最小化、即時識別並有效圍堵。

07 · STRUCTURAL CONTROLS

應用層模式：微服務化、最小權限與獨立身分

Microsoft · OWASP · Palo Alto
Pattern 01

將 Agent 設計為微服務

應避免打造擁有過多工具與模糊職責的「Everything Agent」。比照分散式系統將代理切割為職責單一的小型元件，再由編排器組合複雜能力；惟須權衡過度切割帶來的編排複雜度與延遲。

Pattern 02

Zero-Trust 最小權限

所有工具與資料存取皆須明確授權（預設為零），並優先將權限綁定單一任務生命週期或採短效憑證。API Token 應由應用程式碼管理與執行，避免直接暴露給模型。

Pattern 03

獨立且可驗證的代理身分

Agent 絕不能共用人類使用者的過寬身分，否則無法分辨是人還是代理在操作。獨立身分（如綁定 user_id + agent_id）能落實精準隔離、單點撤銷憑證與多代理稽核，防範 Agent Impersonation。

MCP（Model Context Protocol）外部整合治理原則

雖然 MCP 支援 HTTP 傳輸授權，但該授權屬選配且無法取代企業存取控制。組織必須完整盤點並隔離未核准的 MCP Server、驗證每項整合的最小權限範圍，並持續審查工具定義變更以防範惡意竄改。

08 · RUNTIME CONTROLS (1/2) · MICROSOFT & OWASP

執行期防線：確定性 HITL 與通道序列控制

Deterministic Gates
01

確定性 Human-in-the-Loop（HITL）

在設計代理審查機制時，最致命的錯誤是讓機率模型自行判斷「何時需要人工審核」；因為能夠繞過任務的對抗輸入，同樣也能說服模型跳過審批流程。

正確架構必須將「推理」與「執行授權」分離，由編排層（Orchestrator）在程式碼中確定性強制觸發，並在刪除資料、變更權限或轉帳等工具呼叫當下即時介入。

02

通道區隔與能力組合限制

系統必須明確標記並區隔外部不可信資料（網頁、郵件與 RAG 文件），在輸出端以確定性程式碼檢查結構，並結合 RAG Triad 評估上下文相關性與事實根據以偵測語意偏離。

同時，編排層應實施 Capability Composition Limits，監測並攔截多個合法工具串接出越權結果的異常呼叫序列。

08 · MEMORY HYGIENE (2/2) · MEM0 & SUNIL ET AL.

記憶生命週期六階段防禦與閾值校準兩難

Memory Lifecycle

Mem0 記憶生命週期六階段防禦流程

Sunil et al. (2026) 記憶淨化閾值的校準兩難

過濾閾值若設定過於嚴格，系統會誤殺合法記憶並大幅降低 Agent 的任務實用性；若過於寬鬆，則會讓 MemoryGraft 等無觸發詞的隱蔽攻擊穿透。因此實務上不存在萬能閾值，必須依業務風險容忍度動態校準，並搭配 TTL（Time-to-Live） 限制未被偵測記憶的存活窗口。

09 · SYNTHESIS & DISCUSSION

綜合對照與讀書會討論：三大共識與思辨問題

Cross-Source Insights
OWASP LLM01 × Microsoft

共識 1：機率性模型無法取代確定性應用層

OWASP 指出 RAG 與微調皆無法根治 Prompt Injection；Microsoft 則從架構面給出解釋——模型層天生具有機率性，唯有開發者完全可控的應用層才能建立確定性的權限邊界與人工審批閘門。

TopAIThreats × Microsoft × Palo Alto

共識 2：無攻擊者自主越權與 MCP 新邊界

2026 年評估事件證明 Agent 僅因目標導向最佳化就可能自主越權，加上未受治理的 MCP 連線擴張，共同支撐了反對萬能代理與強制 Zero-Trust 授權的立場。

Palo Alto × Mem0

共識 3：持久性與高內部信任使記憶更隱蔽

Semantic Imitation Heuristic 讓 Agent 將檢索到的記憶視為自身成功經驗來模仿，導致單獨看無害的文字仍能引發跨會話行為漂移，必須比照生產資料庫加以治理。

讀書會三大思辨問題

01 確定性與自主性的張力
如果最安全的作法是微服務切割、確定性 HITL 與任務級授權，這會在多大程度上削弱 Agent 解決開放式複雜問題的能力？實務上該如何切分兩者的邊界？

02 記憶淨化閾值的校準兩難
面對 MemoryGraft 這類不依賴觸發詞的經驗嫁接攻擊，除了靜態過濾閾值與 TTL 過期機制外，是否能設計出具備上下文感知能力的記憶驗證方式？

03 合法單體組合出越權序列
當「讀取檔案」與「發送 HTTP 請求」各自看來都符合最小權限時，編排層應該如何定義規則並即時偵測出不合法的 Chained Capability Escalation？
